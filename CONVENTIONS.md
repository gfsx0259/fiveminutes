# Rider — как пишем код

Это правило для всего приложения Rider, не только для API.

Код объектный. Поведение живёт в объектах, которые получают зависимости через конструктор и вызывают друг друга. Общий кусок выносится в значение, сервис или трейт, а не копируется.

Статический метод не пишем. Исключение — то, что требует сам язык или библиотека и что нельзя вызвать иначе. Сейчас это `from` у enum и константа `DATABASE` у миграций Cycle: мигратор читает её как константу класса.

Выборки идут через репозиторий Cycle. Репозиторий возвращает одну сущность или `Doctrine\Common\Collections\Collection`. Дальше по результату ходят методами коллекции. Массив как результат выборки не возвращаем.

SQL в коде приложения не пишем, если тот же запрос выражается репозиторием. Схема базы — другое: её меняют миграции, и там SQL остаётся, потому что это не выборка.

ClickHouse Cycle не покрывает. Выборка лидов идёт через репозиторий лида и тоже возвращает коллекцию. Текст запроса живёт только там. Клиент ClickHouse — пакет `beeterty/clickhouse-php-client`, тот же, что в LM API. Свой HTTP-клиент не пишем: остальной HTTP идёт через Guzzle.

PHP-приложение — Yii 3, как LM API. Конфиги лежат в `config`, HTTP идёт через контроллеры, зависимости собирает DI, запрос проходит middleware. Cycle подключён через `yiisoft/yii-cycle`. Точка входа `Environment` статическая: раннер Yii вызывает её до контейнера.

Фронт — Vue 3, Pinia, Vuetify.
