# Rider — как пишем код

Это правило для всего приложения Rider, не только для API.

Код объектный. Поведение живёт в объектах, которые получают зависимости через конструктор и вызывают друг друга. Общий кусок выносится в значение, сервис или трейт, а не копируется.

Статический метод не пишем. Исключение — то, что требует сам язык или библиотека и что нельзя вызвать иначе. Сейчас это `from` у enum и константа `DATABASE` у миграций Cycle: мигратор читает её как константу класса.

Выборки идут через репозиторий Cycle. Репозиторий возвращает одну сущность или `Doctrine\Common\Collections\Collection`. Дальше по результату ходят методами коллекции. Массив как результат выборки не возвращаем.

SQL в коде приложения не пишем, если тот же запрос выражается репозиторием. Схема базы — другое: её меняют миграции, и там SQL остаётся, потому что это не выборка.

ClickHouse Cycle не покрывает. Выборка лидов идёт через репозиторий лида и тоже возвращает коллекцию. Текст запроса живёт только там. Клиент ClickHouse — пакет `beeterty/clickhouse-php-client`, тот же, что в LM API. Свой HTTP-клиент не пишем: остальной HTTP идёт через Guzzle. Сессию Kratos читает `Ory\Client\Api\FrontendApi` из пакета `ory/client`, как в LM API. Идентификаторы выдаёт `Ramsey\Uuid\UuidFactory`, тоже как в LM API. Свой генератор UUID не пишем.

Класс исключения заканчивается суффиксом `Exception`: `NoSessionException`, не `NoSession`.

Имя из другого пространства имён подключается через `use` и дальше пишется коротко. Полное имя с ведущим `\` не используем: `use DomainException;`, затем `throw new DomainException(...)`.

Поле, которое конструктор сохраняет без изменения, объявляется в параметре конструктора. Отдельное объявление и присваивание `$this->field = $field` не пишем. Если значение перед записью меняется, поле остаётся отдельным: промоушен записывает аргумент сразу, а readonly-свойство повторно не записать.

Класс, который не меняет поля после конструктора, объявляется `readonly`, и тогда все его свойства тоже только для чтения. Если меняется только часть полей, `readonly` ставится на остальные свойства. Класс не может быть `readonly`, когда он наследует обычный класс — команду Symfony, исключение, форму ввода, репозиторий Cycle — и когда это сущность Cycle: ORM строит от неё прокси-наследника. У такой сущности `readonly` остаётся на полях, которые после конструктора не меняются.

PHP-приложение — Yii 3, как LM API. Конфиги лежат в `config`, HTTP идёт через контроллеры, зависимости собирает DI, запрос проходит middleware. Cycle подключён через `yiisoft/yii-cycle`. Точка входа `Environment` статическая: раннер Yii вызывает её до контейнера.

Данные на входе HTTP разбирает и проверяет форма. Формы лежат в `App\Api\Form`, отдельно от контроллеров. Класс наследует `Yiisoft\Input\Http\AbstractInput`, помечается атрибутом источника (`#[FromBody]` и соседние из `yiisoft/input-http`) и описывает поля атрибутами `yiisoft/validator`. Собирает форму `ValidatingHydrator` из пакета `yiisoft/hydrator-validator`: резолвер параметров передаёт её в экшен. Невалидный ввод даёт `InputValidationException` и ответ 400 с полем `errors`. Ручной разбор `getParsedBody()` и свои проверки полей запроса не пишем.

Фронт — Vue 3, Pinia, Vuetify.
